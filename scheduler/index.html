Your business
Alerts when a customer books, changes, or cancels

Tip: Gmail may skip the phone alert for mail your own account sends to itself. Use a different address here (like your business email) or turn on phone push below.

How to set up phone push
  1. Install ntfy from the Play Store or App Store.
  2. Tap Generate above, then Save settings.
  3. In ntfy, tap +, type the exact topic name, and subscribe.
  4. Press Send test alert below.

Alerts only say what happened (a new booking, a change, a cancellation), never a name, phone number, or address. Tap one to open the Scheduler. Anyone who knows a topic name can read its alerts, so keep the generated name private.

Connection
Go live (one time, about 10 minutes on a computer)

Bookings, emails, and calendar events run on a free Google Apps Script in your own Google account. No monthly fees.

  1. Open sheets.new to make a new Google Sheet. Name it Splash Bookings.
  2. In the sheet: Extensions → Apps Script. Click in the code, press Ctrl+A (Cmd+A on a Mac), then Delete, so the editor is completely empty.
  3. Copy the booking server code and paste it in. Scroll to the bottom: the last line must be // ---- END OF FILE (Splash Booking backend) ----. Delete anything below it.
    View code
  4. Near the top, change 'CHANGE-ME' to your own passcode: 10 or more characters that aren't a word, name, date, or phone number. Press save.
  5. setup is already picked in the function menu next to Run. Press Run and approve the permissions. Google warns that it hasn't verified the app because it's your own private script. Choose Advanced → Go to … (unsafe). If Google lists checkboxes, tick Select all, then Continue or Allow.
  6. Deploy → New deployment, gear icon → Web app. Set Execute as: Me and Who has access: Anyone. Press Deploy and copy the Web app URL.
  7. Paste the URL in Connection above, press Connect, and enter your passcode.
  8. For short, clean customer links, put the same URL in book/config.js in your GitHub repo.

Updating to newer server code later: paste over the old code the same way and save (no need to change the passcode or run setup again), then Deploy → Manage deployments → Edit → Version: New version → Deploy. The URL stays the same.
